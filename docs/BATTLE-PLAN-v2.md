The judges will see P&L. They'll see MCP and CLI integration. They'll see autonomous agents making decisions. They'll see a multi-agent architecture that's genuinely novel.

## VI. THE OPTIONS STRATEGY

Every agent MUST trade options (hackathon requirement). Initial strategy pool:

### Conservative (for clones of top performers):
- **Covered Calls:** Buy 100 shares SPY/QQQ, sell OTM call. Collect premium.
- **Cash-Secured Puts:** Sell OTM put on stock we want to own. Collect premium.

### Moderate (for agents that need more alpha):
- **Bull Put Spreads:** Sell OTM put, buy further OTM put. Defined risk.
- **Bear Call Spreads:** Sell OTM call, buy further OTM call. Defined risk.
- **Iron Condors:** Sell OTM put spread + OTM call spread. Profit in range.

### Aggressive (for agents going for the win):
- **Long Calls/Puts:** Directional bets on earnings/macro events
- **Straddles/Strangles:** Volatility plays around earnings
- **Calendar Spreads:** Sell near-term, buy far-term. Theta play.

Each agent picks from this menu based on Ernie's wire data and their own mutation parameters.

## XII. THE HEARTBEAT — 5-Minute Real-Time Execution

The 5-minute monitor is a pure Python script (no_agent=True cron). No LLM, no tokens. Just code hitting Alpaca's API directly. Fast, cheap, relentless.

### Architecture: Two-Layer Execution

**Layer 1: THE HEARTBEAT (every 5 minutes, no_agent=True)**
- Python script: `/mnt/agent_share/gordon/hackathon/heartbeat.py`
- Cron schedule: `*/5 * * * 1-5` (every 5 minutes, weekdays only, 9:30 AM - 4:00 PM ET)
- Uses Alpaca REST API directly (requests library, not MCP — too slow for 5-min cycle)
- Reads from the fresh hackathon paper account only

**What the Heartbeat does every 5 minutes:**
1. Pull all positions from hackathon account
2. For each position:
   - Check stop-loss: if current price <= stop → MARKET SELL immediately
   - Check profit target: if current price >= target → MARKET SELL immediately
   - Check options expiration: if option expires today → alert (auto-close at 3:30 PM)
   - Check assignment risk: if ITM option near expiry → alert
3. Pull all open orders, check for fills
4. Check for pending trade plans from the Options Gauntlet (queued orders file):
   - If a trade plan is queued and market is open → execute via Alpaca API
   - Mark plan as executed in the queue
5. Update the positions log file (for website dashboard to read)
6. Only send Telegram alert if: stop hit, order filled, anomaly detected, or compliance violation
7. Silent if nothing happened — no spam

**Rate limit management:**
- Alpaca Trading API: 200 requests/minute (free tier)
- 5-minute cycle = 12 cycles/hour = 78 cycles/day
- Each cycle: ~15-20 API calls (positions, orders, quotes for 10 agents)
- Total: ~1,560 calls/day — well within limits
- Monitor X-RateLimit-Remaining headers, back off if needed

**File-based communication:**
- `/mnt/agent_share/gordon/hackathon/state/positions.json` — current positions (heartbeat writes, dashboard reads)
- `/mnt/agent_share/gordon/hackathon/state/orders.json` — open orders
- `/mnt/agent_share/gordon/hackathon/state/trade_queue.json` — pending trade plans from Options Gauntlet
- `/mnt/agent_share/gordon/hackathon/state/heartbeat.log` — execution log
- `/mnt/agent_share/gordon/hackathon/state/alerts.json` — alerts for Gordo to review

**Layer 2: THE ORCHESTRATOR (agent crons at key times)**
- 6:00 AM: Ernie's Wire (agent cron)
- 6:15 AM: Gordo capital allocation (agent cron)
- 12:00 PM: Mid-day report (agent cron)
- 4:00 PM: Market close — Richard risk audit + Charlie compliance audit (agent cron)
- 4:30 PM: Gordo ranks, fires, publishes HR board (agent cron)
- 5:00 PM: EOD report + X post + email (agent cron)
- 6:00 PM: Clone + reallocate capital (agent cron)
- 7:00 PM: Options Gauntlet begins (agent cron — runs the 6-step process for each new agent)

The Heartbeat handles real-time execution. The Orchestrator handles strategy, firing, replication, and reporting. Two layers, no overlap.

### Heartbeat Script Pseudocode:

```python
# heartbeat.py — runs every 5 minutes during market hours
import requests, json, datetime

API_KEY = os.environ['HACKATHON_ALPACA_KEY']
API_SECRET = os.environ['HACKATHON_ALPACA_SECRET']
BASE_URL = 'https://paper-api.alpaca.markets/v2'

# 1. Check market open
clock = alpaca_get('/clock')
if not clock['is_open']:
    exit(0)  # silent — market closed

# 2. Pull all positions
positions = alpaca_get('/positions')

# 3. For each position, check stops and targets
for pos in positions:
    symbol = pos['symbol']
    current_price = float(pos['current_price'])
    avg_entry = float(pos['avg_entry_price'])
    
    # Load stop/target from state file
    plan = load_trade_plan(symbol)
    
    if plan['stop_loss'] and current_price <= plan['stop_loss']:
        # STOP HIT — SELL NOW
        alpaca_sell(symbol, pos['qty'])
        log_alert(f"STOP HIT: {symbol} at {current_price}, stop was {plan['stop_loss']}")
        send_telegram(f"🔴 STOP HIT: {symbol} exited at ${current_price}")
    
    elif plan['profit_target'] and current_price >= plan['profit_target']:
        # TARGET HIT — SELL NOW
        alpaca_sell(symbol, pos['qty'])
        log_alert(f"TARGET HIT: {symbol} at {current_price}, target was {plan['profit_target']}")
        send_telegram(f"🟢 TARGET HIT: {symbol} exited at ${current_price}")

# 4. Check pending trade plans from Options Gauntlet
queue = load_trade_queue()
for plan in queue:
    if plan['status'] == 'pending' and market_open:
        # Execute the queued trade plan
        if plan['asset_class'] == 'option':
            execute_option_order(plan)
        else:
            execute_equity_order(plan)
        plan['status'] = 'executed'
        log_alert(f"EXECUTED: {plan['symbol']} {plan['side']} {plan['qty']}")

# 5. Update state files for dashboard
save_state('positions.json', current_positions)
save_state('orders.json', open_orders)

# 6. Silent exit if nothing happened (no_agent = no spam)
```
